# WorkTrack V28.0.9 — Attendance Persistence Hardening

## Purpose
Strengthen the attendance persistence path after V28.0.8 testing showed that 30 September 2026 could appear immediately after saving but disappear after a full refresh.

## Changes
- Supabase client reads use `cache: "no-store"` to prevent stale attendance responses.
- Attendance save continues to use the database unique key `user_id,work_date`.
- After upsert, the exact date is read back with up to three verification attempts.
- The selected month is reloaded from Supabase after a successful save instead of relying on a session-only record.
- A final exact-date check runs after the full reload; the app does not show a success message if the persisted row cannot be confirmed.
- Dashboard month controls are forced to remain side-by-side on mobile.
- No Supabase schema, RLS policy, or SQL migration changes are included.
